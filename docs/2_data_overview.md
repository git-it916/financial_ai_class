# 데이터 개요와 EDA 진행 방향

기준: 2026-10-11 (KST). 연구 설계와 원래 EDA 계획은 `docs/plan.md.md`에 있습니다. 이 문서는 **지금 실제로 가진 자료**와, 그 자료로 EDA를 어떤 순서로 진행할지를 정리합니다. 기간 표기(P_pre·P0·P1·P1_late·P2)와 괴리 정의(①·②)는 계획서를 따릅니다.

## 요약

- 무료 자료 대부분은 받았습니다. 서울 현물·매매기준율·금리는 ECOS로 2016년부터 받았고, 스왑포인트는 KMB로 2023-10부터, NDF 체결은 DTCC로 2024-10부터 받았습니다.
- **계획서의 주자료인 KRX 미국달러선물은 아직 없습니다.** API 키가 401(권한 없음)이라 승인 대기로 보입니다. 그래서 06:00 KST 야간 괴리(주 가설 후보)는 아직 계산할 수 없습니다.
- 수집하며 새로 확인한 사실이 계획을 바꿉니다(3장).
  - DTCC 원화 NDF는 하루 약 8,300건으로 매우 두텁습니다. 그래서 **15:30 KST 같은 시각 괴리를 무료로 잴 수 있습니다.** 대조 통화 4개도 같은 형식으로 들어 있습니다.
  - **ECOS '종가'(731Y003 0000013)는 P2에서 기준 시각이 바뀐 것으로 보입니다**(02:00에서 새벽 06:00 무렵으로).
- 그래서 EDA는 'KRX 없이 지금 할 수 있는 것'(4.2)과 'KRX가 들어오면 할 것'(4.3)으로 나눠 진행하자고 제안합니다.

## 3. 수집하며 새로 확인한 사실

### 3.1 DTCC로 15:30 같은 시각 괴리를 잴 수 있음

DTCC 파일은 그날 체결만 담은 것이 아니라 **누적 보고서**입니다. 과거 거래의 종료(TERM)·정정(CORR)·오류(EROR)·압축(COMP)·경개(NOVA)가 섞여 있습니다. 그래서 `Action type = NEWT`, `Event type = TRAD`, `UPI FISN`이 'Fwd NDF'인 행만 남기고 `Dissemination Identifier`로 중복을 지웠습니다. 남은 신규 체결의 99.1%는 체결일과 파일 날짜가 같습니다.

- 원화 NDF 신규 체결은 2년간 약 490만 건입니다. 평일 중앙값은 하루 8,292건이고, 10분위수도 4,815건입니다.
- 만기는 80%가 25~40일입니다(중앙값 34일, 현물 결제일 + 1개월). 3개월물(75~100일)은 약 5%입니다.
- 시간대(KST)별로는 09~17시가 가장 많고, 21~01시가 그다음입니다. 02~06시는 시간당 하루 100~250건 수준입니다. **06~09시는 하루 십여 건으로 거의 비어 있습니다.** 그래서 06:00 짝의 NDF 값은 직전 30분(05:30~06:00) 체결로 만들어야 합니다.

**시험 계산:** 15:30±5분의 1M 체결 중앙값을 NDF로 쓰고, 서울 선물환은 'ECOS 15:30 종가 + KMB 1M 스왑포인트 중간값'으로 두었습니다. 이렇게 잰 괴리 ①은 하루 약 158건의 체결로 만들어지고, 분포는 중앙값 6bp, 표준편차 51bp입니다. 계획서가 예상한 '수십 bp' 규모와 맞습니다. 다만 KMB 1M 호가 폭의 절반이 1M 연율로 약 37bp라, 스왑포인트 쪽 잡음이 괴리 크기와 비슷합니다. 이 계산은 측정 가능성 점검용입니다. 정의(시간 창, 만기 보정, 스왑포인트 출처)는 4.1의 원칙대로 P2를 빼고 정해야 합니다.

> 기록: 위 시험 계산에서 기간별 요약값(P2 포함)을 한 번 출력했습니다. 정의 확정에는 그 값을 쓰지 않습니다.

### 3.2 ECOS '종가'의 기준 시각이 P2에서 바뀜

DTCC 1M 체결가에서 KMB 스왑포인트를 빼 '현물 환산값'을 30분 구간별로 만들고, ECOS 값과 가장 가까운 구간을 찾았습니다.

| ECOS 시리즈 | P1에서 가장 가까운 KST 구간 | P2에서 가장 가까운 KST 구간 |
| --- | --- | --- |
| 15:30 종가 | 15:30 (중앙 차이 0.47원) | 15:30 (0.69원) |
| 종가(0000013) | 01:30~02:00 (0.53원) | 06:30, 03:30, 05:00 (0.68~0.71원) |

P1의 종가는 02:00 마감 값이 맞습니다. P2의 종가는 새벽 시간대 값이고, 06:00 무렵 마감 값일 가능성이 큽니다. 새벽에는 가격이 거의 안 움직여 구간이 뚜렷하게 갈리지 않으므로, 한국은행 통계 설명이나 보도자료로 확인해야 합니다. 이 확인이 중요한 이유는 두 가지입니다.

- 확인되면 **P2에서는 ECOS 종가 + DTCC 05:30~06:00으로 06:00 같은 시각 괴리를 KRX 없이도 잴 수 있습니다.**
- 하지만 P1에는 06:00 역내 현물이 없습니다. 그래서 P1_late 대 P2 비교에는 여전히 KRX 야간 종가가 필요합니다.

### 3.3 네이버 기사에서 NDF 최종호가와 서울외국환중개 스왑포인트를 뽑을 수 있음

'NDF 최종호가' 검색 결과 중 664건의 기사 요약에 "1,440.50원에 최종 호가" 형식의 수치가 있습니다. 날짜로는 2026-02-13 ~ 10-08 사이 154일입니다. 같은 문장에 '최근 1개월물 스와프포인트(-1.50원)'(서울외국환중개 기준)도 들어 있습니다. 다만 API가 검색어당 최근 1,099건만 주므로, 매일 받아 쌓아야 기간이 늘어납니다. 이 자료는 두 가지 검증에 씁니다.

- 뉴스 NDF 값의 기준 시각 확인: DTCC 체결과 대조
- KMB 스왑포인트 중간값을 써도 되는지 판정: 서울외국환중개 값과 대조

### 3.4 품질 점검 결과

- 모든 파일에서 중복 키는 0건이고, DTCC 733개 파일은 모두 읽힙니다. 열이 70개인 파일 1개는 2021년 파일로, 옛 형식입니다.
- **KMB 외환의 시가·고가·저가·종가는 KMB 중개분만 집계한 값입니다.**
  - MAR은 ECOS와 728일 모두 같습니다.
  - 시가·고가·저가·종가는 같은 날끼리 4~10%만 일치하고, 차이의 중앙값은 0.4~0.8원입니다.
  - KMB 고가는 99.9%의 날에 ECOS 고가 이하이고, KMB 저가는 모든 날 ECOS 저가 이상입니다.
  - 그래서 시장 전체 시가·고가·저가·종가는 ECOS를 쓰고, KMB 외환에서는 거래금액만 씁니다.
- **원본의 오기로 보이는 값:**
  - BAP 2021-04-21·22: 두 날이 같은 행으로 반복되고, 저가 48.83이 고가 48.43보다 큽니다.
  - BAP 2021-05-20: 시가가 478.855로 찍혀 있습니다(47.855의 오기로 보임).
  - 대만 중앙은행 2025-06-30: 종가 29.902가 앞뒤 날(29.18, 29.185)과 크게 다릅니다.

  분석할 때 이 값들을 표시하고 빼야 합니다.
- yfinance 일봉은 약 8%의 행이 시가·고가·저가·종가 관계(고가 ≥ 저가 등)에 맞지 않습니다. 일별 분석에는 쓰지 않습니다.
- ECOS 대만달러/달러는 아침 고시 기준이라, 하루 안에 크게 움직인 날(예: 2025-05-02 대만달러 급등)에는 대만 종가와 1원 넘게 차이 납니다. 대조군 역내 가격으로는 대만 중앙은행 종가를 씁니다.
- DTCC 원화 체결이 평일에도 적은 날은 크리스마스, 신정, 성금요일입니다(50~7,000건).

## 4. EDA 진행 방향

### 4.1 그대로 지킬 원칙 (계획서 6.0에서)

1. **정의는 처치 전 자료로만 정합니다.** DTCC 방식은 2024-10-09 ~ 2026-07-03으로 정하고, P2는 품질 점검에만 씁니다. 정한 내용은 `analysis_decisions.md`에 날짜와 함께 커밋한 뒤 결과를 봅니다.
2. **같은 측정 방식끼리만 비교합니다.** ECOS 종가처럼 기간 사이에 기준 시각이 바뀐 자료는 기간 비교에 쓰지 않습니다.
3. **서머타임 표본끼리 비교합니다.** P2(2026-07-06 ~)는 지금까지 서머타임 기간뿐입니다. 2026-11-01부터 06:00 짝에 1시간 시차가 생깁니다.
4. 주 가설 하나를 미리 정하고, 나머지 비교는 다중검정을 보정합니다.

### 4.2 KRX 없이 지금 할 수 있는 것

순서는 뒤 단계가 앞 단계의 결정에 기대는 순서입니다.

**1단계. 정제 파이프라인 (eda_00)**

계획서 5장의 `src/clean/`을 처음 만드는 단계입니다.

- `sessions`: UTC 시각에 KST, 세션(주간·A·B·C), 기간(P_pre~P2), 미국 서머타임 여부, 거래일을 붙이는 함수입니다. 거래일은 KST 09:00을 경계로 하고, 새벽 체결은 전 거래일에 귀속합니다.
- `dtcc`: 3.1의 필터를 적용합니다.
  - 정정·취소 처리, 3.1의 신규 체결 필터
  - 프라임브로커 거래(`Prime brokerage transaction indicator = TRUE`, 체결의 약 40%)가 같은 거래를 두 번 보고하는지 확인
  - 패키지 거래 표시
  - 이상가격 제거(같은 10분 체결 중앙값에서 k×MAD 이상)
  - 만기 분류(1M·3M, 허용 오차)
  - 결과는 `data/processed/dtcc_ndf.parquet`(5개 통화)로 저장합니다.
- `events.yaml`을 계획서 초안에서 실제 파일로 만듭니다. '확인' 항목을 검증하고, 2024-10-09 WGBI 발표, 2025-04-03 관세, 2024-12-03 비상계엄 등을 넣습니다.
- 산출물: T01 데이터 사전, T02 품질 요약(3.4를 표로), F01 커버리지 히트맵.

**2단계. 측정 가능성과 잡음 하한 (eda_01·02)**

- **ECOS 종가 기준 시각 확정:** 3.2를 한국은행 자료로 확인합니다. 매매기준율 산정 구간이 P2에서 바뀌었는지도 함께 봅니다. 매매기준율은 NDF 정산 기준가라서, 바뀌었다면 괴리 정의에 바로 영향을 줍니다.
- **NDF 쪽 잡음:** 시간 창(±2·5·10분) 안에서 DTCC 체결가의 흩어짐으로 중앙값의 표준오차를 잽니다. 창을 넓힐 때 생기는 시차 잡음과 맞바꾸는 관계를 보고 창 폭을 정합니다.
- **서울 쪽 잡음(가장 큰 위험):**
  - KMB 스왑포인트 고시 시각을 확인합니다.
  - KMB 중간값을 네이버 기사 속 서울외국환중개 1M 스왑포인트와 비교합니다.
  - 1M 스왑포인트를 NDF 각 체결의 실제 일수에 맞게 환산하는 규칙(일수 비례, 1M·2M 보간)을 정합니다.
  - KMB 호가 폭이 괴리 크기와 비슷하므로, 이 단계에서 'KMB 중간값을 주 측정에 써도 되는가'를 판정합니다.
- **06:00 NDF 값 만들기:** 05:30~06:00 체결 수와 마지막 체결 시각 분포를 봅니다. 서머타임이 아닌 기간에는 뉴욕 마감이 07:00이므로 06:30~07:00도 함께 봅니다.
- **뉴스 NDF 기준 시각:** 네이버에서 뽑은 최종호가(154일)를 DTCC 30분 구간과 대조합니다. 뉴욕 17:00 ET 무렵인지 확인합니다.
- **실측 괴리 규모:** P1(2024-10 ~ 2026-07-03)의 15:30 같은 시각 괴리로 '참' 괴리의 크기와 분산을 잽니다. 계획서는 KRX로 하려던 것인데, DTCC 15:30으로 먼저 할 수 있습니다. 이 값이 이후 최소 검출 효과 계산의 기준이 됩니다.
- **Gate 1 판정 메모:** 주 측정 조합, 주 만기, 스왑포인트 출처, KRX·단말기가 꼭 필요한지.

**3단계. 괴리 정의 확정 (eda_03, 처치 전 자료만)**

- 내재금리 정의(계획서 6.3), 달러 T-bill 4주·3개월, 원화 CD 91일, ①과 ①+②를 함께 저장합니다.

- 산출물: `analysis_decisions.md` v1 커밋.

**4단계. 지금 자료로 가능한 새 분석 두 가지**

계획서에는 없지만, DTCC가 5개 통화를 같은 형식으로 담고 있어 무료로 할 수 있습니다.

- **NDF 거래 활동의 시간대 이동:**
  - 24시간 전환 뒤 새로 열린 02:00~09:00 KST에, 역외 NDF 거래의 비중(체결 건수·명목금액)이 주간 대비 줄었는지 봅니다. 역내에서 바로 헤지할 수 있게 되면 그 시간대 NDF 수요가 줄 것이라는 계획서 0.5의 메커니즘을 직접 보는 지표입니다.

### 4.3 KRX가 들어오면 할 것

- 야간 마감(06:00) 가격을 주자료로 하는 06:00 같은 시각 괴리. NDF 쪽은 뉴스 대신 DTCC 05:30~06:00을 쓸 수 있어 표본이 늘어납니다(P1_late 274일, P2 70일).

- 야간 종가 신선도와 측정 도구 변화(P1_late 대 P2 야간 거래량)를 봅니다.
- **경로 B 본 계산:** (06:00 괴리 − 15:30 괴리)를 P1_late 대 P2로, 서머타임 표본끼리 비교합니다. 15:30 쪽은 4.2에서 이미 준비됩니다.

## 5. 자료 갱신 방법

프로젝트 루트에서 실행합니다. 이미 받은 부분은 건너뛰거나 이어서 받습니다.

```
set PY=%USERPROFILE%\.venvs\fxbasis\Scripts\python
set PYTHONIOENCODING=utf-8
set EXTERNAL_DATA_DIR=%CD%\data\external

%PY% -m src.collect.dtcc --workers 4      :: 매일. 받은 날짜는 건너뜀
%PY% -m src.collect.yf_intraday           :: 매일(평일). 1분봉 누적
%PY% -m src.collect.naver                 :: 매일. 최근 기사 누적
%PY% -m src.collect.kmb swap --start 2023-10-12
%PY% -m src.collect.ecos
%PY% -m src.collect.krx                   :: KRX 승인 후. 월별 중간 저장
%PY% -m src.collect.gdelt                 :: 429면 대기 후 재시도, 오래 막히면 저장하고 종료
```

한 번만 받으면 되는 것(다시 돌려도 됨): `fred`, `nyfed`, `bis`, `cboe`, `cbc_tw`, `bap`, `kmb fx`, `fomc`. 이 수집기들은 파일을 통째로 덮어씁니다. KMB 외환처럼 사이트가 최근 몇 년치만 주는 출처는, 다시 받으면 오래된 날짜가 빠질 수 있습니다. 다시 받을 때는 `data/interim`을 먼저 백업합니다.
